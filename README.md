A machine-checked Lean 4 proof of **Theorem 4.1** of Alexeev–Putterman–Sawhney–Sellke–Valiant,
*Short proofs in combinatorics, probability and number theory II*
([arXiv:2604.06609](https://arxiv.org/abs/2604.06609), §4), which answers
[Erdős Problem 1091](https://www.erdosproblems.com/1091) in the **negative**.

Prize ledger entry: **JSP-000907** (`TheJustinSunPrize/awards`).

---

## The question and the answer

> Is there a function `f(r) → ∞` such that every graph `G` with chromatic number 4, all of
> whose subgraphs on at most `r` vertices are 3-colourable, contains an odd cycle with at
> least `f(r)` chords?

**No.** For every `m ≥ 1` there is an explicit `K₄`-free graph `Gₘ` on `20m + 31` vertices with
`χ(Gₘ) = 4`, every proper subgraph 2-degenerate (hence 3-colourable), and **every** cycle
carrying at most **10** chords. The chord bound is an absolute constant while the local
colourability parameter `r` grows with `m`, so no `f(r) → ∞` can exist.

`Gₘ` is a caterpillar of pentagonal blocks — spine blocks `S₀ … Sₘ`, each a 5-cycle carrying
leaf blocks that are themselves 5-cycles — plus one special vertex `v` joined to four vertices
of every leaf block. Every vertex other than `v` has degree exactly 3. The construction is
deliberately asymmetric (`S₀` has no *c*-leaf, `Sₘ` has no *a*-leaf); that asymmetry is what
forces non-3-colourability, and it lives in exactly one place in the source,
`Block.validB` in [`Erdos1091/Construction.lean`](Erdos1091/Construction.lean).

## The top-level theorem

[`Erdos1091/Main.lean:224`](Erdos1091/Main.lean) — verbatim:

```lean
theorem erdos_1091.variants.counterexample :
    ∃ C : ℕ, ∀ m : ℕ, 1 ≤ m →
      ∃ (n : ℕ) (G : SimpleGraph (Fin n)),
        m ≤ n ∧ n ≤ C * m ∧ G.CliqueFree 4 ∧ G.chromaticNumber = 4 ∧
          (∀ H : G.Subgraph, H ≠ ⊤ → H.coe.chromaticNumber ≤ 3) ∧
          (∀ c : G.Cycle, c.chords.encard ≤ 10)
```

**This statement is not ours.** It is taken character-for-character from
[`google-deepmind/formal-conjectures` PR #5870](https://github.com/google-deepmind/formal-conjectures/pull/5870),
which is statement-only: the theorem there is a `sorry`. This repository supplies that proof,
so the work drops into the PR without touching the signature. That removes the usual
"is the Lean statement really the problem?" risk — the statement was written by a third party.

## Known limits

Three deliberate departures from the paper's route, none of which weakens the final theorem or
adds a hypothesis to any statement — `cycle_chords_le_ten` keeps its signature verbatim:

1. Cycles avoiding `v` are proved to have at most **5** chords where the paper proves exactly 0.
   Proposition 4.10 only needs ≤ 10, and a pentagon has only 5 rim edges; proving "a cycle
   inside a `C₅` is the `C₅`" would be extra work for no gain.
2. Cycles through `v` are counted by chord *type* (≤ 6 at `v`, ≤ 4 rim) rather than the
   paper's per-block 4+4+1+1. Same edges, same total of 10, no block-tree case analysis.
3. Rim chords are counted by an injection into blocks (`Finset.card_biUnion_le`) rather than a
   global sum.

Tightening 1 and 2 back to the paper's exact intermediate statements is the only work left to
make the Lean development match the paper lemma for lemma. Nothing beyond §4 of the paper is
formalised, and no claim is made about any other result in it.
